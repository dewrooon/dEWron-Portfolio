# dEWron — портфолио

Адаптивный сайт на React и Vite с БЭМ-стилями.

## Запуск

```sh
npm install
npm run dev
```

В PowerShell при ограничениях скриптов используйте npm.cmd.

## Сборка

```sh
npm run build
npm run preview
```

Статический сайт собирается в dist/.

## Структура

- src/App.jsx — композиция страницы.
- src/components/ — навигация, подвал, общий заголовок раздела.
- src/sections/ — смысловые разделы и их стили.
- src/index.css — дизайн-токены, сброс, контейнер и общие элементы.
- public/ — статические ресурсы.

Повторяющиеся карточки создаются из массивов данных. Услуги, проекты и стек редактируются в соответствующих секциях; контакты — в Contact.jsx.

Проекты обозначены как запланированные или на подготовке. Миниатюры являются визуальными концепциями. Supabase — используемый и изучаемый сервис.

Реализованы мобильное меню, клавиатурный фокус, переход к содержимому и поддержка prefers-reduced-motion. Контакты открывают Telegram и почтовый клиент.

## Маршрутизация

React Router DOM подключён через RouterProvider. Маршруты описаны в src/router/router.jsx:

- / — Home, страница портфолио;
- * — NotFound, страница для неизвестных адресов.

src/layouts/SiteLayout/SiteLayout.jsx содержит общие Header, Footer и Outlet. Новые страницы размещайте в src/pages/ИмяСтраницы/ и добавляйте в children маршрутизатора. Внутренние переходы между страницами используйте через Link; внешние URL и mailto остаются обычными ссылками.

Ссылки навигации вида /#projects работают и с других страниц. Layout прокручивает страницу к разделу при изменении маршрута.

При публикации BrowserRouter требует SPA fallback: сервер должен отдавать index.html для адресов приложения, не совпадающих с файлами. Это позволяет открывать и обновлять вложенные адреса напрямую.

## Проекты из Supabase

Секция получает записи существующей таблицы projects через src/services/projects.js. Публикуются только записи is_published = true; сначала идут is_featured = true, затем новые по created_at. technologies поддерживает массив строк или строку со значениями через запятую. github_url отображается как ссылка, если содержит HTTP(S) URL.

Запрос использует точные поля таблицы: title, description, image_url, project_url, github_url, technologies, is_published, is_featured, created_at. project_url добавляет ссылку «Открыть проект». Поля id и status не требуются. Без изображения показывается нейтральная обложка; без названия — «Проект». Локальных демонстрационных записей больше нет.

Для отображения необходимы опубликованные записи и SELECT-доступ через RLS для посетителей. Клиентский фильтр не заменяет RLS: политика базы должна разрешать анонимное чтение только опубликованных записей. Схема и политики существующей базы этой доработкой не изменены.

## Редактор проектов

Откройте `/admin` и войдите через Supabase Auth. После проверки `is_admin` доступны обзор, все проекты (включая черновики), создание, редактирование, публикация, скрытие и удаление с подтверждением. Избранным может быть только опубликованный проект. Картинки задаются URL, загрузки файлов в Storage нет.

Редактор использует `id` как первичный идентификатор, по примеру панели. При создании база должна генерировать `id` и `created_at`. Администратору необходимы SELECT/INSERT/UPDATE/DELETE-политики; серверные права должны проверяться в RLS. Сохранение и удаление подтверждаются возвратом изменённой строки, поэтому нулевой результат не считается успешным.

- `src/pages/Admin/Admin.jsx` — доступ, навигация и обзор.
- `src/pages/Admin/components/` — вход, список и форма проекта.
- `src/pages/Admin/useAdminAccess.js` — проверка сессии и роли.
- `src/pages/Admin/projectForm.js` — преобразование и валидация формы.
- `src/services/adminProjects.js` — запросы управления проектами.

Проверки формы: `node --test src/pages/Admin/projectForm.test.js`.
